# 经典算法、场景适配与公平对比协议

## 基线算法

| 算法 | 代码入口 | 雄安窄路密网适配 |
| --- | --- | --- |
| 固定配时 | `FixedTimeAlgorithm` | 采用全网统一的八相位保护左转/直右相位集，3 个决策周期保持一个相位，避免任一转向长期饥饿。 |
| MaxPressure | `MaxPressureAlgorithm` | 将每个路口的四向 12 个车道状态映射到八个可控相位，按相位服务进口的实时排队量选择动作。 |
| TRANSYT 风格 | `TransytStyleAlgorithm` | 用需求滑动平均计算绿信比，并以共同周期及依据拓扑坐标生成的偏移实现走廊协调；这是可审计复现，不声称为商业 TRANSYT 软件。 |

## 场景适配

场景位于 `data/xiong_an_20/`，包含 20 个 CityFlow 控制路口、4 x 5 近似网格拓扑、相邻路口连接和四向边界进口。`flow_morning.json`、`flow_midday.json`、`flow_evening.json` 由原始路口 15 分钟左/直/右转需求生成；`source_signal_plans.json` 保存原始配时以便审计。

原始路口配时的相位文本和周期并不完全一致。因此，实验不将异构文字配时错误地逐项强制映射，而是在全部算法与自研算法间统一采用八相位保护左转/直右相位集。相邻连接及折线道路仍由 CityFlow 保留；斜向来车在控制器观测中归并到最近的东西或南北进口组。

## 公平对比协议

1. 每次比较只选一个时段，所有方法使用完全相同的 `roadnet.json`、`flow_<period>.json`、7500 个仿真步、10 秒决策间隔和 CityFlow 版本。
2. 所有方法在同一 20 路口集合上控制，单线程复算（`--threads 1`），并由 `configs/xiong_an_20.yaml` 记录固定随机种子 `20260816`。
3. `src/run_cityflow.py` 是唯一指标计算入口，输出总需求、已完成车辆估计、吞吐率、平均旅行时间、自由流延误、末端在网车辆和排队代理量。
4. 每组结果保留命令参数、算法名、时段和步数在 `metrics.csv` 中；运行 `scripts/summarize_baselines.py` 形成统一指标表。不得用不同场景、流量、时长或指标口径替换其中任何一项。

候选参数网格完整记录于 `configs/baseline_parameter_grid.yaml`。正式比较固定使用其中 `selected_for_comparison` 的组合，避免在测试集上继续调参造成不公平比较。

## 结果归档与复现

`结果/历史基线指标汇总.csv` 保存历史结果的可审阅转录。当前版本的正式复现通过 `scripts/run_task3_aligned_baselines.ps1` 运行，按时段和算法写入 `结果/任务3对齐复现/<period>/<algorithm>/`。本次最终 Docker 验证输出位于 `结果/最终验证_transyt_morning/`，包含 `metrics.csv`、轨迹、动态流和 CityFlow 配置。
