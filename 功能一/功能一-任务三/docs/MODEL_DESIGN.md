# 模型设计：UGAT / C-MP / FRAP

## 1. 总的想法

任务三要回答的问题是：AI/智能决策模型到底怎么帮上忙——不是"我们用了强化学习"这种空话，而是真的解决拥堵疏散或协同控制，并且结果能复现。我们最后定的路线是：

1. **训练 UGAT**：UGAT（Uncertainty-aware Grounded Action Transformation，官方仓库 [DaRL-LibSignal/UGAT](https://github.com/DaRL-LibSignal/UGAT)，论文 [arXiv:2307.12388](https://arxiv.org/abs/2307.12388)）解决的是仿真到现实（Sim-to-Real）的迁移问题。仿真里练好的策略直接拿到真实路网，性能通常会掉，UGAT 就是处理这个落差的。
2. **冻结 UGAT、嵌入 C-MP**：UGAT 权重训完就冻住，只当参考分支；真正做在线决策的是 C-MP（协同最大压力，[arXiv:2407.01421](https://arxiv.org/abs/2407.01421)）——它没有可训练参数，每个路口只看本地车道信息算压力、选相位，天然适合走廊协同，结果也最好复现。
3. **CityFlow 里验证 1×3 绿波**：在一条 3 路口的串联走廊上把绿波跑出来，跟固定配时/无协同策略对比，看协同控制对拥堵疏散的实际效果。

FRAP（相位竞争，官方仓库 [gjzheng93/frap-pub](https://github.com/gjzheng93/frap-pub)）是另一个学习型模型，用在 20 路口和 4×4 扩展工程里，和 UGAT 组合做相位选择。

## 2. UGAT 到底是什么（按官方论文说清楚）

> 之前简写版文档里把它说成"前向模型 + 逆模型"，这里按论文（arXiv:2307.12388）的准确说法纠正一下，正式名称是 **Uncertainty-aware Grounded Action Transformation（带不确定性的接地动作转换）**：

- **接地动作转换（Grounded Action Transformation）**：给定当前状态 `s_t` 和策略 `π_θ` 给出的动作 `a_t`，转换网络输出一个"接地动作" `â_t`——也就是在目标环境动力学下更有效的那个动作。它不是换掉策略，而是对策略动作做校正。
- **不确定性量化**：转换网络同时输出这个转换有多可靠（不确定性）。**只有不确定性低于阈值时才采用转换后的动作**，否则保留原始策略动作——模型没把握的时候不乱改，避免把仿真和现实的差距放大。
- **动态阈值**：阈值 α 不是拍脑袋定的，每轮跑完根据历史不确定性的均值更新。论文实验里动态阈值比固定阈值效果好。
- **训练流程**：先在仿真环境里预训练策略 M 轮；用当前策略在仿真和真实环境各跑一轮采数据；训练转换网络和不确定性估计器；评估时按阈值决定用不用转换动作。

**落到我们任务里**：UGAT 权重是团队训练出来的（`model/ugat1x5_best.pt` 等），训练完直接冻结（`requires_grad=False`），在线决策交给 C-MP，UGAT 只作为迁移/参考分支。这样组合，既保留了模型的迁移能力，又保证结果可解释、可对比、可复现。

## 3. C-MP 怎么算压力

C-MP 对每个允许的 movement `(l,m)` 算一个压力：

```
P(l,m) = x_up(l) × [1 + β·r_up(l)] − x_down(m) × [1 − α·r_down(m)]
```

- `x` 是车辆数，`r` 是这条 lane 的瞬时平均车速/限速（速度比，没车时记 0）；
- `β=0.60` 是上游车队优先权，`α=0.60` 是下游自由流折减系数，都能用命令行覆盖；
- 一个相位的压力 = 它所有允许 lane-link 的压力之和，控制器选压力最大的相位；最小绿灯时间 `t_min=10s` 内不切相位；
- 每个路口只看本地信息，**去中心化**，所以天然适合走廊、绿波这种协同场景。

## 5. 状态、动作、奖励怎么定义的

| 要素 | 定义 |
|---|---|
| 状态（1×3/1×5，主交付） | 每个路口的本地车道车辆数、速度比、当前相位等；rank 输入维度 8/6/8/12/12 |
| 状态（20路口/4×4） | 20 维 = 12 维车道需求（4 方向 × 左转/直行右转/直行右转）+ 8 维当前相位 one-hot |
| 动作（1×3/1×5） | 按路口 rank 有 2/1/2/4/4 个相位动作 |
| 动作（20路口/4×4） | 0..7 共 8 个相位：东西/南北直行右转、保护左转、四向综合；平台内动作 0 是 3 秒清空相位 |
| 奖励/目标（C-MP） | 无——规则控制器，评估 Travel Time、throughput、queue、delay_ratio_apx |
| 奖励/目标（C-MP-FRAP 训练） | `y = reward_frap - EMA(reward_cmp_teacher)`，相对 C-MP teacher 的 advantage，Double-DQN + Huber loss |
| 奖励/目标（20路口/4×4） | 推理无显式奖励；适配器训练用 Q 值 MSE（raw_mse 只观察训练过程，不当评测指标） |

车道需求顺序（`src/run_cityflow.py::collect_state`）：`[W左,W直右,W直右, E左,E直右,E直右, N左,N直右,N直右, S左,S直右,S直右]`。

**指标口径**：`delay_ratio_apx = 1 - 平均车速/限速`，无量纲、通常 0..1。旧日志里 `delay_type=real` 输出的是累计真实延迟总量，**不能**跟 apx 口径直接比（见 `outputs/4x4_frap/DELAY_UNIT_NOTE.md`）。

## 6. 几条硬约束

- **UGAT 一律冻结**：`requires_grad=False`，加载/训练时由 `UGATFRAPController.assert_frozen()` 强制检查，不微调基座。
- **规则先验 + 学习修正**：C-MP 给可解释的安全基础动作；学习型模型只在 C-MP 拿不准时小幅修正（压力差 ≤ 2.0、残差范围 ±0.25、每路口覆盖率 ≤ 2%）。
- **固定随机种子**：1×3/1×5 正式评测 `seed=4444`；20 路口 `seed=20260816`。
- **1×5 → 1×3 的原因**：1×5 走廊太长、效果不佳，现实中也很少有这么长的串联路网；收敛到 1×3 后优化两遍，作为最终绿波场景（详见 `docs/ABLATION.md`）。
